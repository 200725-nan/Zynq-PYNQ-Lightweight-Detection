# AX7021 实板运行视频录制操作指南

本指南用于录制 AX7021 上的 C1 固定图像检测过程，供现场演示视频制作。目标是让观众在一段清楚、可信的视频里看到实物板卡、实际运行、串口结果和对应的板上图像输出。

## 1. 本次要展示的真实过程

当前已完成的 C1 板测输入为一张固定 RGB 图像，帧 ID 是 `000000005001.rgb`。数据流为：

**RGB888 输入 → PL Q0.6 缩放到 300×300 → 双 store AXI VDMA → DDR → ARM/Linux Float32 SSD-MobileNetV1 检测。**

已记录结果：

- 检测结果：16 个目标，runner 错误数 0。检测 JSON SHA-256：`45a3c46fef940053cd7ec2b812987e909ddc32e4cd9fc40a2fc6070b09a0db9b`。
- 板上输出：270,000 字节 RGB，与 Q0.6 golden 逐字节一致。SHA-256：`32a909f74381cd06e989bf8ec9241b1c85479d7ec9d3ba17f8588bfbbc7e4778`。
- DMA helper：4.014 ms；ORT wall time：2.505 s；输入文件就绪至后处理结果：2.578 s。
- 首次启动推理 session 约需 84.4 s；拍摄时可完整保留等待过程，成片可加简洁的“模型初始化”字幕。

## 镜头里的技术亮点

视频除了拍到板卡成功运行，也要让观众看懂这套实现为什么值得看。结果画面旁可以用 3 张简洁字幕卡逐项呈现：

1. **PL 与 ARM/Linux 协同：** PL 完成 Q0.6 RGB888 缩放，双 store VDMA 负责 DDR 帧交接，ARM/Linux 完成 Float32 目标检测。
2. **行缓存节省片上存储：** 2 个 RAMB36E1 完成 Q0.6 行缓存；相较四缓冲映射，BRAM36 用量减少 50%，独立实现 WNS +0.384 ns。
3. **实板结果逐字节可查：** AX7021 输出 RGB 与 golden 完全匹配；16 个检测结果、0 个 runner 错误，日志与 SHA-256 可复核。

字幕卡应与板卡实拍、终端完成行和同次运行结果图依次出现。展示资源指标时注明这是 XC7Z020 100 MHz routed 实现数据；展示计时则注明这是本次固定帧板测数据。
同次运行的日志和结果见：

- `02_C1_实板结果/board_evidence_manifest.json`
- `02_C1_实板结果/board_evidence/c1_runner_no_uio.log`
- `02_C1_实板结果/board_evidence/c1_result_no_uio.jsonl`
- `02_C1_实板结果/board_evidence/output_000000005001.rgb`
- `02_C1_实板结果/board_evidence/c1_board_frame_annotated.png`

片中使用的结果图必须对应本次拍到的运行 ID 和帧 ID；如复用已有结果图，在画面中标注“本项目 AX7021 固定帧实测输出”。

## 2. 拍摄设备与连接

### 推荐方式：手机拍全景，电脑保留终端

1. AX7021 用稳定电源供电；USB-UART 接电脑。板卡、转接线和电源位置整理整齐，板卡丝印和接口朝向镜头。
2. 串口工具选择当前实际枚举出的端口。上次记录使用 **COM6、115200 baud、8 data bits、无校验、1 stop bit（8N1）**；本次拍摄先在 Windows 设备管理器确认端口号。
3. 串口成功登录后停在 `root@zynq:~#` 提示符。把串口窗口放大，调整字体，让运行状态和结果行可读。
4. 手机横屏，建议 1920×1080、30 fps。使用三脚架或固定支架，让一个画面同时包括 AX7021 实物和电脑终端；手机与屏幕略成角度以减少反光。
5. 若一个镜头无法同时清楚拍到板卡和屏幕，使用第二台相机或 OBS 屏幕录制终端。开拍前两边各拍一下手或同时说出同一个短口令，方便后期对齐时间。

### 串口端口使用规则

COM6 同一时间只能由一个程序占用。若本次已验证的运行工具会通过 COM6 自动收发串口数据，就让该工具独占端口，并用 OBS/相机拍下它的运行输出；不要同时打开串口助手。若由串口助手交互执行已验证命令，则使用串口助手作为唯一端口程序。

串口工具中看到 `root@zynq:~#` 提示符后，直接在输入行输入实际命令；不要把提示符本身复制进去。登录凭据不录入视频，也不把密码显示在镜头中。

## 3. 开拍前准备

### A. 建立本次运行卡

由负责板卡运行的人在开拍前填写并复核：

- 日期、板卡型号/版本、运行负责人：
- 串口端口及参数：
- C1 BIT、DTB/FDT、runner、模型和推理库版本/哈希：
- 输入文件：`000000005001.rgb`；输入 SHA-256：`9a472e6dbbb6d7c51ca0e4bdef578a85195a7660967d351dda569bb2250e02af`
- 本次运行 ID：
- 已验证的完整启动/运行命令（逐字粘贴）：
- 输出目录、日志文件名和结果导出位置：

执行命令沿用项目负责人确认的成功运行配方。板卡运行所需的 BIT/FDT、模型、ARM32 推理库和输入素材，由负责人按已验证运行配方准备并核对哈希。

### B. 摆好画面

1. 擦净板卡和镜头，收起无关线材；将 AX7021 放在画面中心。
2. 电脑桌面只保留串口/运行窗口、对应的结果图查看器和本次运行资料目录。
3. 关闭消息通知；终端字号调到观众能读到 `FRAME_OK`、`detections=16` 和错误计数。
4. 结果图查看器先打开本次输入图；板上运行完成后，再打开同一 run 导出的 RGB/标注图。旁边可显示帧 ID 和 RGB SHA-256 的前后几位。
5. 不要提前打开检测框图片后冒充实时显示。若运行完成后才展示结果图，字幕写“同次运行导出的板上结果”。

## 4. 录制顺序与镜头脚本

建议录成一段 90–120 秒的横屏素材，最终成片控制在 3 分钟内。

### 镜头 1：设备与系统（约 8–12 秒）

手机从整体缓慢移近 AX7021，清楚拍到板卡丝印、供电和 USB-UART 连接。画外音可说：

> “这是 AX7021 Zynq-7000 开发板。当前演示运行 PL Q0.6 RGB888 缩放、双 store VDMA 帧传输和 ARM/Linux 目标检测。”

### 镜头 2：输入与终端（约 8–12 秒）

拍电脑屏幕上的串口参数、root 提示符、帧 ID 和已复核的运行卡。不要让画面出现密码、个人账户或无关通知。

画外音：

> “本次使用项目记录的固定帧 `000000005001.rgb`，运行版本和输入哈希已记入实验记录。”

### 镜头 3：实际运行（约 40–90 秒）

1. 开始连续拍摄后，先让镜头同时看到板卡和终端 3–5 秒。
2. 运行负责人按已核对的配方启动本次 C1 运行。命令执行时保持终端和板卡都在画面内。
3. 模型 session 初始化约 84 秒时，可保持镜头不动；若视频时长需要剪短，原始长视频仍须保留，剪辑版用字幕标明“中间等待已快进”。
4. 等待出现完成行。成功记录应能看到类似：

```text
FRAME_OK 000000005001.rgb store=0 detections=16
C1_SOURCE_RUN input=1 completed=1 errors=0 session_init_ms=84405.444
```

实际数字以本次终端输出为准，勿手工输入或补造成功行。

### 镜头 4：展示对应图像结果（约 12–20 秒）

运行结束后，展示同次运行导出的 300×300 RGB 或其检测标注图。画面中同时给出帧 ID、检测数、输出尺寸和 RGB 与 golden 一致的核验结果。需要重新拍显示器时，让镜头拍到屏幕和板卡；需要清晰录屏时，用 OBS 录制同一电脑画面，再与手机全景按口令对齐。

画外音：

> “本次板上输出为 300×300 RGB888，共 270,000 字节，与 Q0.6 golden 逐字节一致；ARM/Linux 检测返回 16 个结果。”

### 镜头 5：计时与结束状态（约 8–12 秒）

展示结果日志或本次 manifest 中的三项计时：DMA helper 4.014 ms、ORT wall 2.505 s、输入就绪到后处理结果 2.578 s。注明计时单位和输入类型。最后镜头回到 AX7021 全景，并停留 3 秒。

## 5. OBS 屏幕录制设置（可选）

如果安装了 OBS，可将终端和结果画面清晰录下来，再与手机拍摄的板卡全景合成：

1. 新建场景“AX7021 实板演示”。
2. 添加“显示器采集”或“窗口采集”，选择串口/运行窗口所在显示器；再添加摄像头作为“视频采集设备”，将板卡画面放在角落。
3. 画布设为 1920×1080，输出 1920×1080、30 fps；录制格式选 MKV 以降低异常中断损坏风险，结束后在 OBS 内转封装为 MP4。
4. 音频保留解说和启动口令；正式拍摄前录 10 秒试听，确认终端字清楚、没有串口电流声盖住语音。
5. 若没有摄像头，OBS 录屏与手机实拍同时开始，用拍手/口令对齐；后期将终端画面做画中画或左右分屏。

没有 OBS 时，手机全景可以独立完成整段拍摄；终端字号调大，尽量让板卡与屏幕同时清楚入镜。

## 6. 文件保存与成片

建议创建以下目录：

```text
03_演示视频/AX7021现场录制/
├─ raw/                 # 相机原始素材，不剪辑
├─ screen_capture/      # OBS 或串口终端录屏
├─ run_evidence/        # 本次运行日志、JSONL、manifest、输出 RGB 和标注图
└─ AX7021_C1_live_demo_YYYYMMDD.mp4
```

- 保留原始手机视频和 OBS 文件；剪辑成片另存，不覆盖源素材。
- 最终 MP4 使用 H.264/AVC，时长 ≤3 分钟，文件 ≤300 MB。
- 可加入架构标题、实测数字和同次 run 的哈希；字幕注明固定图像输入。
- 剪辑版快进初始化等待时，片尾或时间轴字幕说明快进区间；关键启动、运行完成和结果校验过程保持可辨认。
- 导出后从头播放检查声音、终端字、图像清晰度和字幕；确认打开正常、画幅横向、帧率稳定、时长和大小合规。

## 7. 录完后的验收

- [ ] 画面能辨认 AX7021 实物及连接状态。
- [ ] 串口/运行窗口显示了这一次真实执行过程和成功结果行。
- [ ] 帧 ID 是本次输入；输出 RGB/检测图与本次 run ID、manifest 对应。
- [ ] 原始 RGB SHA-256 与 manifest 一致；`bytes_equal=true`。
- [ ] 检测计数、错误数和计时来自同次运行日志。
- [ ] 原始素材、录屏、run evidence 和最终 MP4 分目录保存。
- [ ] MP4 为 H.264/AVC，时长不超过 3 分钟，大小不超过 300 MB。
- [ ] 登记表已填写视频路径、SHA-256、负责人、复核人和验收结果。
