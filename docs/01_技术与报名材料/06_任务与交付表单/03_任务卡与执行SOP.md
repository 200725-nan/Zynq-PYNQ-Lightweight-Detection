# 任务卡与执行 SOP

先在 `04_全部交付物登记表_含GitHub.md` 填负责人和截止时间。完成后附上文件/URL、复核人和验收结果，并更新任务状态。

## T1｜现场视频与照片（优先级 P0）

**目标：** 录制真实 AX7021 板卡运行演示，另拍作品全貌图及最多 4 张板卡角度图。详细步骤见交接包根目录 [AX7021 实板视频录制操作指南](../AX7021_实板视频录制操作指南.md)。完整镜头和录制顺序见交接包根目录 [AX7021 实板视频录制操作指南](../AX7021_实板视频录制操作指南.md)。

**前置：** 先向项目负责人确认板卡当前启动状态、可安全使用的已验证镜像和恢复方式；禁止为了录视频自行写 SD/闪存或换未经核对的 BIT/FDT。准备相机/手机、稳定支架、光线和干净桌面。保护屏幕中的 Wi-Fi 密码、账号、串口命令、个人信息。

**步骤：**
1. 开拍前记下板卡、BIT/FDT、软件/模型版本和输入来源；对着镜头拍到 AX7021 丝印、供电/接口和运行终端/显示器。
2. 用项目已经确认可重复的运行流程启动，不临时发明命令。若当前只能重放固定帧，就口头/字幕说明“固定帧实验”；不可把屏幕动画冒充摄像头实时处理。
3. 连续录下启动、帧输入/处理、可见检测框或输出、结束状态及时间信息。画面同时呈现 AX7021 板卡和实际结果；保留连续操作关键片段，并在旁注中说明剪辑位置。
4. 保存原始视频；另导出 MP4、H.264/AVC，时长不超过 3 分钟、文件不超过 300 MB。可剪去等待空白，但保留连续操作的关键片段。
5. 拍一张能看清完整作品连接关系的全貌 JPG/PNG（≤10 MB），再拍最多 4 张板卡/接口角度图（每张≤10 MB）。
6. 写旁注：拍摄日期、设备、输入来源、实际流程、重复次数、任何剪辑；把素材路径填进登记表。

**验收：** 原始素材完整；实物 AX7021、实际运行过程和结果清晰可见；拍摄说明标注输入类型与剪辑；视频和照片规格符合赛事要求。

## T2｜GitHub 仓库创建/发布（P0）

**目标：** 把 `04_源码快照` 发布到由团队权利人控制的 GitHub 仓库，并登记可验证 URL（报名字段 ≤200 字符）。

**前置：** 由仓库所有者登录其 GitHub 账户；确认源码贡献者/授权、第三方许可证和是否可公开。由所有者创建仓库并登记实际 HTTPS URL。发布内容以源码快照为准；模型、数据集、运行库、凭据、个人信息和生成物均排除在发布清单外。

**步骤：**
1. 复制 `04_源码快照` 到干净目录或使用包内快照；检查 `.gitignore`、文件清单、`SHA256SUMS.txt`。
2. 运行敏感信息/大文件检查，人工复核命中；确认许可证策略后再建仓库。不得替实际权利人选择或伪造许可证。
3. 由团队指定所有者建立仓库；推荐先设 Private 完成文件清单和提交核验，再由所有者决定改 Public。仓库名建议 `ax7021-zynq-edge-detection`，组织/个人归属由团队决定。
4. 初始化 Git，提交说明建议 `Prepare AX7021 C1 competition handoff snapshot`。推送后检查默认分支、README、文件数量、哈希；用无登录浏览器/另一位成员核验访问权限。
5. 将 HTTPS 仓库主页 URL（必要时再登记 commit SHA）写入交付表。公开仓库需确认不泄露个人信息或未授权 IP。
6. 同一源码基线再生成比赛要求的 RAR（≤200 MB），记录压缩包哈希并解压抽查。

**验收：** URL 可打开且指向正确仓库；提交 SHA 可追溯；源码与快照范围一致；许可和权利人已确认；发布文件清单通过复核；RAR 大小与可读性符合要求。

## T3｜技术报告 PDF（P0）

1. 从 `01_技术与报名材料/AX7021_technical_report_draft.docx` 开始；先获取官方模板/版式要求。
2. 按系统架构和板上 manifest 更新文字；测量数据注明输入、次数和计时范围。
3. 加入清楚的系统框图、真实板上输出图和关键数字；注明 Q0.6/RGB888、VDMA、ARM/Linux Float32 检测。
4. 在 Word 导出 PDF；检查字体嵌入、公式/图表、页码、目录、图片清晰度、乱码/空白页、≤50 MB。登记模板版本、PDF SHA-256 和复核人。

**验收：** 官方要求齐全；每个数能追溯到本包证据；限制如实；最终 PDF 打开无排版问题且大小合规。

## T4｜有边界的低风险优化实验（P1，可让位给交付）

**推荐实验：** ARM ORT intra/inter 线程组合小扫描，输入仍用同一 C1 固定帧/同一 BIT、FDT、模型和 runtime。按固定输入、完成帧数和实测耗时记录结果。

1. 先核对当前设备软件包/启动态由硬件负责人确认；只用已经认可的运行入口，不改启动介质。
2. 在同一块板和同一输入上，设定一组明确组合（建议 intra/inter=0/1、1/1、2/1）；每组 1 次 warmup + 3 次正式重复。若时间不足，先只对照 0/1 与 2/1。
3. 固定模型、输入 RGB、BIT/FDT、温度/供电和检测容差；一次仅改线程数。记录初始化、DMA、ORT wall、端到端时间及 CPU 状态。
4. 每次要求 0 error；检测数量/框/分数与参考输出在既定容差内；写入 JSONL 和摘要，不覆盖旧记录。
5. 报告每组中位数/范围；样本少时称“探索性测量”。若无稳定改善，保留默认配置，不扩大实验。

**停止条件：** 一旦出现错误、输出差异或状态不明，停止该组，不连续重跑或自行改板级状态；保存日志交负责人判断。
